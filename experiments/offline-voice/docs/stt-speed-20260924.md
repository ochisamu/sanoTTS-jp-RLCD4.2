# STT timing follow-up (2026-09-24)

On RLCD4.2 ESP32-S3 240 MHz / 8 MiB PSRAM, unchanged 6-layer W8A8 model,
stored 6.6-second public reference clip, 273 output frames. No microphone capture
or TTS time included. These are measurements of one input, not latency percentiles.

| Variant | Three STT times, ms | Decision |
| --- | --- | --- |
| Prior firmware | 13,566 (one immediately preceding run) | Baseline |
| Periodic scheduler yield | 13,001 / 12,992 / 12,992 | Adopt |
| Periodic yield + SRAM weight-row copy | 13,136 / 13,127 / 13,125 | Reject and remove |

Median improvement versus the baseline: 574 ms / 4.23%, not a major speedup.
All six candidate runs produced frame-argmax hash `bb0f0a32` and the same
reported PSRAM free size (7,630,208 bytes at STT completion). This is single-clip
recognition parity, not a new independent accuracy assessment.

`runtime/ctc_runtime.c` now checks elapsed time at existing cooperative points,
yielding one RTOS tick after at least 20 ms instead of sleeping at every matrix
tile/output-row group. This preserves arithmetic, weights and decode logic and
retains scheduler opportunities. It is not a hard real-time 20 ms deadline;
checkpoint intervals depend on work size. The runtime remains non-reentrant.

Host checks: kernel self-test and all native logits match the old qa5 output
byte-for-byte for the reference clip, including the subsequently rejected row
buffer candidate. Eleven CTC/phoneme/silence-trimming regression tests passed.

Only app partition 0x10000 is written. STT, TTS, LM, partition table and bootloader
are unchanged. Local logs and fallback app are in
`.cache/rlcd-bpe-deploy-20260924/`; the pre-change app is
`before-stt-scheduler.bin`. Restore it at 0x10000 if needed, keeping the BPE layout.
Earlier `deployment.json` describes the pre-optimization firmware, not the new app.

## Next experiments, not implemented here

1. Speech endpoint detection: stop capture after a conservative silence interval,
   preserving initial/final consonants and pauses. This cuts the fixed five-second
   capture wait, not the encoder's compute cost. Requires noisy/quiet live tests.
2. Train a smaller encoder student with CTC/representation distillation, compare
   against the six-layer teacher on held-out speakers and silence/noise cases.
   Existing three-layer baseline best dev PER is 27.30%, versus six-layer 13.57%
   FP32 (optimized runtime 14.49%). Do not ship it solely for lower latency.
3. Profile per-layer memory traffic and consider dual-core projection work only
   with bounded allocations, watchdog tests and full output regression.

Shrinking/distilling Moonshine retains upstream model-license considerations;
it does not produce MIT weights. See the publication review before distributing.
